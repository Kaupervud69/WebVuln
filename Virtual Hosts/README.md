# Виртуальные хосты (Virtual Host)

**Виртуальный хост (VHOST)** — это механизм, используемый веб-серверами (например, Apache, Nginx, IIS) для размещения нескольких доменов или поддоменов на одном IP-адресе. При перечислении веб-сервера стандартные запросы часто направляются только на основной или стандартный VHOST. Скрытые хосты могут открывать дополнительные функции или уязвимости.

## Инструменты

- **wdahlenburg/VhostFinder** — идентификация виртуальных хостов через сравнение схожести.
- **codingo/VHostScan** — сканер виртуальных хостов, который можно использовать с инструментами для pivot-атак, обнаруживает catch-all сценарии, алиасы и динамические страницы по умолчанию.
- **hakluke/hakoriginfinder** — инструмент для обнаружения исходного хоста за обратным прокси. Полезен для обхода облачных WAF.

  ```bash
  prips 93.184.216.0/24 | hakoriginfinder -h https://example.com:443/foo
  ```

- **OJ/gobuster** — инструмент для перебора директорий/файлов, DNS и VHOST, написанный на Go.

  ```bash
  gobuster vhost -u https://example.com -w /path/to/wordlist.txt
  ```

## Методология

Когда веб-сервер размещает несколько сайтов на одном IP-адресе, он использует виртуальный хостинг, чтобы определить, какой сайт обслуживать при поступлении запроса.

В HTTP/1.1 и выше каждый запрос должен содержать заголовок `Host`:

```
GET / HTTP/1.1
Host: example.com
```

Этот заголовок сообщает серверу, к какому домену обращается клиент.

- **Если на сервере только один сайт:** заголовок `Host` часто игнорируется или устанавливается значение по умолчанию.
- **Если на сервере несколько виртуальных хостов:** веб-сервер использует заголовок `Host` для внутренней маршрутизации запроса к нужному содержимому.

### Пример конфигурации

Предположим, сервер настроен так:

```apache
<VirtualHost *:80>
    ServerName site-a.com
    DocumentRoot /var/www/a
</VirtualHost>

<VirtualHost *:80>
    ServerName site-b.com
    DocumentRoot /var/www/b
</VirtualHost>
```

Запрос с хостом по умолчанию (`site-a.com`) возвращает содержимое сайта A:

```
GET / HTTP/1.1
Host: site-a.com
```

Запрос с изменённым хостом (`site-b.com`) возвращает содержимое сайта B (возможно, открывая что-то новое):

```
GET / HTTP/1.1
Host: site-b.com
```

## Идентификация VHOST-ов

Установка заголовка `Host` в другие известные или предполагаемые домены может дать различные ответы.

```bash
curl -H "Host: admin.example.com" http://10.10.10.10/
```

### Признаки того, что вы попали на другой VHOST

| Признак | Описание |
|---|---|
| **Разные HTML-заголовки** | Другие title, meta-описания или названия бренда |
| **Разный Content-Length / размер тела ответа** | Отличается от стандартного |
| **Разные статус-коды** | 200 вместо 403 или редирект |
| **Свои страницы ошибок** | Нестандартные страницы 404, 403 |
| **Цепочки редиректов** | Перенаправление на совершенно другие домены |
| **Сертификаты** | Сертификаты с Subject Alternative Names (SAN), перечисляющие другие домены |

## Дополнительный метод: история DNS

Используйте историю DNS-записей, чтобы выявить старые IP-адреса, ранее связанные с доменами вашей цели. Затем протестируйте (или «подберите») текущие доменные имена против этих IP-адресов.

**Результат:**  
Если это сработает, вы сможете обнаружить реальный адрес сервера и обойти защиты, такие как Cloudflare или другие WAF, взаимодействуя напрямую с исходным сервером (origin server).

## Дополнительное объяснение

### Простая аналогия

Представь, что у тебя есть многоквартирный дом с одним адресом (IP). В нём живут разные люди (сайты). Чтобы почтальон (запрос) понял, кому именно нужно доставить письмо, он должен указать не только адрес дома, но и имя получателя (заголовок `Host`). Если он укажет имя несуществующего жильца, письмо может быть доставлено тому, кто живёт по умолчанию (обычно в первую квартиру), либо вообще отклонено.

VHOST-сканирование пытается подобрать такие имена, чтобы получить доступ к «квартирам», которые не видны снаружи, но могут содержать ценные вещи (скрытые сайты, панели управления, тестовые версии).
